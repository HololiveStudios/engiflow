01 — INFRAESTRUTURA

Decisão de Stack e Hospedagem

Duas zonas: Cloudflare (edge-native, zero ops de servidor) e VPS apenas para o bridge WhatsApp persistente. O VPS não carrega API, banco ou front.

☁ Cloudflare Pages

FRONTEND — REACT + TS
  • Dashboard interno (painel operacional)
  • Portal do cliente (subdomínio separado)
  • Deploy automático via Git / CDN global
  • Build por especialidade via feature flags
CF PAGES

⚡ Cloudflare Workers

API — TYPESCRIPT EDGE
  • API REST modular por especialidade
  • Autenticação JWT + RBAC multi-papel
  • Scheduled Worker: motor de vencimentos (cron)
  • Geração de PDF (certificados e laudos)
  • Integração nativa D1 / KV / R2
CF WORKERS

🟣 VPS Dedicado

WHATSAPP BRIDGE — GO
  • Go + whatsmeow — cliente WA Web
  • Processo contínuo (sessão persistente)
  • Recebe mensagem → POST para Worker API
  • SQLite local para sessão WA
  • ~R$40/mês, 2GB RAM é suficiente
VPS — GO

🗄 Cloudflare D1

BANCO — SQLite MANAGED
  • Banco principal de todas as especialidades
  • Migrations com Drizzle ORM
  • Acesso nativo dentro do Worker
  • Backups automáticos gerenciados
CF D1

📦 Cloudflare R2

STORAGE — ARQUIVOS
  • Certificados PDF (SST), laudos (Elétrica)
  • Plantas e memoriais (Civil)
  • Evidências fotográficas e ARTs
  • Zero custo de egresso
CF R2
Por que D1 e não PostgreSQL? Para B2B multi-especialidade em escala inicial/média, D1 elimina todo overhead de ops — zero backups manuais, zero tuning, acesso direto no Worker. Migração via Hyperdrive disponível se necessário.
VPS obrigatório apenas para WA: whatsmeow precisa de WebSocket persistente — Workers são stateless. VPS leve (~2GB RAM) resolve. Nada mais roda no VPS.

Decisões Técnicas por Camada

CAMADA TECNOLOGIA JUSTIFICATIVA

Frontend portal React + TS + Vite Subdomínio separado, auth própria, mesma base de componentes.

Autenticação JWT + CF KV RBAC: admin, operador, instrutor, engenheiro, cliente.
E-mail Resend Alertas, confirmações, envio de documentos. Integra com Workers.

07 — WHATSAPP

Bridge WhatsApp — Detalhamento

O bridge Go roda no VPS como processo contínuo. Sem lógica de negócio — apenas recebe/envia mensagens e chama a Worker API por HTTPS autenticado por HMAC.

01
whatsmeow mantém WebSocket persistente com servidores WA Web. Recebe qualquer mensagem.
VPS Go
02
Bridge extrai número, texto, timestamp, tipo. Monta payload JSON.
parser
03
POST para /api/wa/inbound no Worker. Autenticado por HMAC secret compartilhado.
HTTPS
04
Worker busca número no D1. Novo → cria lead. Existente → atualiza último contato.
D1
05
Classifica especialidade: SST (treinamento/cert.), Civil (obra), Elétrica (laudo). Rota ao pipeline correto.
logic
06
Worker envia resposta para /api/wa/send no bridge Go. Bridge entrega via whatsmeow.
→ WA
07
Evento registrado no D1. Painel exibe interação. Lead novo: alerta CRM por especialidade.
log
08 — DIFERENCIAIS

O que torna a plataforma inovadora

🔀

Fluxo automático por especialidade

Sistema detecta o tipo de serviço e abre checklist, etapas e documentos corretos. Zero adaptação manual.

⚡

Financeiro por gatilho operacional

Medição → cobrança. Turma realizada → fatura. Aceite técnico → conta a receber. O financeiro reage à operação.

🔄

Motor de renovação multi-especialidade

Um cron que monitora certs SST, laudos elétricos e inspeções civis. Qualquer vencimento gera alerta + oportunidade.

🔍

QR code de verificação em documentos

Cert SST e laudos elétricos com QR único. Auditoria escaneia e confirma. Hash no D1 — sem terceiro.

📊

Score de conformidade por empresa

0 a 100 por empresa: treinados, vencidos e pendentes por função e filial. Visível no portal — cria urgência.

🌐

Portal self-service por especialidade

Certs SST, laudos elétricos, status civil — sem ligar. Reduz atendimento manual em 60%+.
